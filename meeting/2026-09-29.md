## 회의 주제

오픈소스소프트웨어 수업에서 진행할 팀 프로젝트의 방향을 정하고, GitHub 저장소를 활용한 팀 활동 기록 방법을 논의하였다.

## 회의 내용

### 1. 프로젝트 진행 방식 검토

이번 팀 프로젝트에서 선택할 수 있는 방향을 크게 두 가지로 나누어 검토하였다.

첫 번째 방법은 오픈소스소프트웨어에 대한 보고서를 작성하는 방식이다. 보고서에는 오픈소스소프트웨어의 개요와 역사, 대표적인 오픈소스 프로젝트, 저작권 및 라이선스와 관련된 내용을 조사하여 정리하는 방식으로 진행할 수 있다는 의견이 나왔다.

두 번째 방법은 실제 소프트웨어를 개발하는 방식이다. ChatGPT 등의 도구를 활용하여 팀원들이 하나의 프로그램이나 웹 서비스 등을 함께 제작하고, 개발 과정에서 GitHub를 이용해 협업하는 형태로 진행할 수 있다는 의견이 나왔다.

### 2. 두 방식의 난이도와 특징 비교

팀원들은 두 가지 방법의 난이도와 작업량에 차이가 있을 수 있다는 점을 이야기하였다.

보고서 방식은 직접 프로그램을 개발하지 않아도 된다는 장점이 있지만, 조사한 자료의 정확성과 내용의 완성도가 중요하기 때문에 교수님의 검토가 비교적 세밀할 수 있다는 의견이 나왔다.

반면 소프트웨어 개발 방식은 실제 프로그램을 만들어야 하기 때문에 작업량과 협업 과정이 더 많을 수 있지만, 팀원들이 역할을 나누어 결과물을 제작할 수 있다는 장점이 있다는 의견이 나왔다.

김시훈 팀원은 두 방식 사이에 난이도 차이가 있어 보인다는 의견을 제시하여 두 의견을 면밀히 비교하였으며, 홍현택 팀원은 실제 소프트웨어를 만드는 두 번째 방식이 더 좋을 것 같다는 의견을 제시하였다.

박정인 팀원은 두 방식 모두 가능하지만 교수님의 평가 방식과 요구 수준을 아직 정확하게 알기 어렵기 때문에 신중하게 결정할 필요가 있다는 의견을 제시하였다.

### 3. 소프트웨어 개발 방향에 대한 논의

소프트웨어 개발 방식으로 진행할 경우 어떤 프로그램을 만드는 것이 적절한지에 대해서도 간단히 논의하였다.

복잡한 대규모 프로그램보다는 수업 기간 안에 팀원들이 직접 구현할 수 있는 비교적 간단한 앱이나 웹 서비스를 만드는 것이 현실적이라는 의견이 나왔다.

또한 다른 수업에서 진행하고 있는 프로젝트 경험이나 기존에 생각했던 아이디어를 참고할 수 있기 때문에 새로운 아이디어를 처음부터 완전히 만들어야 하는 부담은 상대적으로 적을 수 있다는 의견도 나왔다.

다만 오픈소스소프트웨어 수업의 프로젝트인 만큼 단순히 프로그램을 만드는 것에서 끝나는 것이 아니라 GitHub를 이용한 버전 관리와 팀원 간 협업 과정도 함께 보여주는 것이 중요하다고 판단하였다.

### 4. 팀원 의견 정리 및 프로젝트 방향 결정

회의 과정에서 여러 팀원이 소프트웨어 개발 방식에 긍정적인 의견을 나타냈다.

최유찬 팀원은 보고서 작성 방식보다 실제 소프트웨어를 만드는 방식이 진행하기 편할 것 같다는 의견을 제시하였다. 홍현택 팀원 역시 시간이 어느 정도 필요하더라도 두 번째 방식이 더 적절해 보인다는 의견을 제시하였다.

전체적으로 두 방식 모두 일정 수준의 작업량이 필요하다는 점에는 의견이 일치하였으며, 팀원들의 의견을 종합한 결과 이번 프로젝트는 두 번째 방식인 실제 소프트웨어 개발 방식으로 진행하기로 결정하였다.

구체적으로 어떤 프로그램을 개발할지와 필요한 기능은 아직 정하지 않았기 때문에 이후 추가 논의를 통해 결정하기로 하였다.

## GitHub 활동 기록 방법 안내

팀 활동 내용을 지속적으로 기록하기 위해 GitHub 저장소의 `members` 폴더를 활용하기로 하였다.

각 팀원은 자신의 이름과 학번으로 생성된 Markdown 파일에 개인 활동 내용을 직접 추가하고, 자신의 GitHub 계정으로 Commit하여 활동 기록을 남기는 방식으로 진행한다.

김서현 팀장은 팀원들이 GitHub 활동 기록을 직접 남길 수 있도록 Markdown 파일을 수정하고 Commit하는 과정을 팀원들에게 안내하였다.

활동 기록 작성 방법은 다음과 같다.

1. 팀 GitHub 저장소의 `members` 폴더에 들어간다.
2. 자신의 이름으로 생성된 `.md` 파일을 선택한다.
3. 오른쪽 상단의 `Edit this file` 버튼을 누른다.
4. 기존 이름과 학번 아래에 자신이 수행한 활동 내용을 작성한다.
5. 작성이 끝나면 `Commit changes...`를 선택한다.
6. Commit message에 자신이 수행한 작업을 간단하게 작성한 뒤 Commit한다.

김서현 팀장은 위 과정을 순서대로 정리하여 팀원들에게 공유하였으며, 각 팀원이 자신의 계정으로 직접 수정하고 Commit해야 개인별 활동 기록이 정상적으로 남는다는 점도 함께 설명하였다.

이를 통해 GitHub 사용에 익숙하지 않은 팀원들도 자신의 활동 내용을 직접 기록할 수 있도록 기본적인 작성 방법을 통일하였다.

- 팀원들의 의견을 종합하여 실제 소프트웨어를 개발하는 두 번째 방식으로 진행하기로 결정하였다.

- 각 팀원이 자신의 계정으로 직접 수정 및 Commit하여 활동 기록을 남기도록 한다.
